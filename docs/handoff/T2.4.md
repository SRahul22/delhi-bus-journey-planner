# T2.4 Deadline and on-time probability (planner)

Status: done for the planner side; door-to-door calibration of the probability is not validated yet (needs eval's realized_val.csv and ml's shifts_d2d.json, T2.6). Gate decisions are for humans.

## What changed
- `GET /journey` takes an optional `arrive_by` (ISO datetime; IST if no offset). 400 on a bad value.
- When it is set, every option gets `on_time_probability = Phi((ln D - mu) / sigma)` with D = arrive_by - depart (s), mu = ln(duration_s), sigma = ln(duration_p85_s / duration_s) / 1.0364 (AGENTS.md section 4). D <= 0 gives 0.
- Ranking with `arrive_by`: the usual selection runs first (labels unchanged), then the option with the highest probability over all candidates is added if missing (label `most_likely_on_time`) and the shown options are sorted by probability (ties: faster first). Without `arrive_by` the response is unchanged apart from new fields.
- New fields (contract 5): per option `band_version`; top level `band_version`, `wait_mode`, `query.arrive_by`.
- Band source (`band_version`):
  - `v1_p85` (default): the v1 band (summed ride p85 + 0.7 x wait in quadrature).
  - `v2_lognormal` (`V2_BAND=1`): A3. Leg components (ride p50/p85 from ml's `predict.band` when present, wait p50/p85 = wait / 1.7 x wait) are combined in log-normal space (Fenton-Wilkinson moment match, independent components), walking added as a fixed part; p85 floored at duration_s.
  - `v2_lognormal+d2d`: also applies ml's `MODEL_DIR\v2\shifts_d2d.json` (T2.6) as a log shift keyed `bucket|peak|offpeak` (or `global`). The file is not published yet, so this path is untested on real shifts.
- Router: when `V2_BAND=1` and `predict.band` exists (ml branch b6c38ca), the per-leg (p50, p85) comes from it; otherwise v1 behaviour.

## Flags
`V2_BAND` (0/1, default 0). `arrive_by` is a query parameter and is always available.

## Validation (19-24 Oct only)
Ride level, 300k validation rides (ml's val19_24.parquet; tables from 1-18), v1 band (p50 = blend600, p85 = summed segment p85), random deadline D = p50 x U(0.6, 1.8), seed 2026:
- all: Brier 0.120, ECE 0.032, mean predicted 0.634 vs observed 0.621.
- by actual ride length: <10 min ECE 0.037; 10-30 0.036; 30-60 0.043; >60 min ECE 0.105 (predicted 0.639 vs observed 0.534: long rides are under-predicted, the known v1 issue).
- reliability: over-confident in the low-middle bins (predicted 0.25 -> observed 0.17; 0.35 -> 0.28), slightly under-confident at 0.6-0.9, over-confident at 0.9-1.0 (0.968 -> 0.942).
(Bucketing by actual length conditions on the outcome; treat the per-bucket numbers as diagnostics.)
Not yet validated: door-to-door probabilities (waits, transfers). That needs realized_val.csv (eval, T0.2) and the d2d shifts (ml, T2.6).
