# T0.3 Metrics and noise floor (eval) -- done

## What changed
- `eval/metrics.py`: every section-4 metric as pure functions on arrays: `error` (median APE, within +-20%, inclusive),
  `bias` (mean/median, s and %), `coverage` (actual <= p85), `width` (median (p85-p50)/p50), `pinball` (tau 0.85),
  `calibration` (share under p50/p85/p90; p90 from the log-normal mu = ln p50, sigma = ln(p85/p50)/1.0364),
  `lognormal_sigma/quantile`, `bucket` (<10, 10-30, 30-60, >60 min by ACTUAL duration), `is_peak` (weekday and
  08:00-10:59 or 17:00-20:59), `by_bucket_peak` (long table per model x bucket x peak, with margins), `noise_floor`.
- `eval/tests/test_metrics.py`: 10 unit tests on toy arrays (unittest; also collected by pytest).
- `eval/noise_floor.py`: noise floor from all GPS traversals (see below).

## Flag
None (measurement only).

## How to run
    python eval\tests\test_metrics.py            (pytest is not installed in either env; unittest runs the same tests)
    python eval\noise_floor.py --set val|test [--keys 50000]

## Results
- Unit tests: 10/10 pass on Windows (system python).
- Noise floor. The card's definition on the 600k sampled test rides is underpowered: only 290 cells (3,391 rides,
  0.6%) have >= 10 sampled rides (val: 14 cells). So `noise_floor.py` uses, for 50,000 sampled ride keys
  (route, board, alight), every map-matched GPS traversal of that stop pair in the same period, cells =
  (route, board, alight, board hour) with >= 10 traversals, error of each traversal vs its cell median:

| Set | Cells | Traversals | Median error | Within +-20% | <10 | 10-30 | 30-60 | >60 min |
|---|---|---|---|---|---|---|---|---|
| val (19-24) | 406,952 | 9.05 M | 10.28% | 74.8% | 11.28% | 9.38% | 9.60% | 11.94% |
| test (25-31, 600k ride keys) | 408,925 | 9.52 M | 10.30% | 75.1% | 11.39% | 9.50% | 9.53% | 11.71% |

  Ride models are at 12.3-13.2% median error, so only ~2-3 points are left to win above the noise floor.
  (In-sample variant on the 290 sampled-ride cells: 10.83%.)
