# T2.6 Door-to-door calibration (shifts_d2d.json)

Owner: ml (+ eval). Status: DONE as a first version on eval's realized_val.csv (version of 19:57 IST), but
**not recommended for serving yet**: the door-to-door miss is a wait bias (p50 problem), which a p85 shift cannot fix.

## What changed
- `model/v3/v2/journey_band.py` (A3, pure python): `combine([(p50, p85), ...])` treats each component (walk, wait,
  ride, transfer) as log-normal (μ = ln p50, σ = ln(p85/p50)/1.0364), sums medians (A3) and gets the spread by
  Fenton-Wilkinson moment matching; P85 = P50·exp(1.0364·σ_T). `journey_band(components, peak)` applies
  `shifts_d2d.json` when present (P85 ×= exp(shift[bucket(P50)|peak]), σ recomputed). `on_time_probability(D, P50, σ)`
  for T2.4. ~10 µs per journey. Tests: `model/v3/v2/tests/test_journey_band.py` (5 pass). Monte Carlo check: with
  sum-of-medians centring (A3) the combined P85 is ~3.4% below the exact P85 of the sum for 3 skewed legs.
- `model/v3/v2/scripts/d2d_shifts.py [csv] [--p50 COL] [--p85 COL] [--a3]`: same method as T1.2 on journey totals:
  s = ln(real_total_s) − ln(plan P85), per bucket(plan P50, section-4 buckets) × peak, ⌈(n+1)·0.85⌉-th score, cells
  with n < 500 pooled with the neighbour. Validation = leave-one-day-out (LODO) over the val days.
  - default: calibrates eval's `plan_p85_s` (v1 duration_p85_s) → `shifts_d2d_v1p85.json`
  - `--a3`: rebuilds plan P85 with `journey_band.combine` from plan_walk_s, plan_wait_s (p85 = 1.7×p50, uniform-wait
    assumption), plan_ride_s/plan_ride_p85_s, plan_transfer_s (×1.7) → `shifts_d2d_a3.json` and `shifts_d2d.json`
    (contract 3 name = the A3 version).
- Input snapshot: `E:\hackathon-work\v2\ml\realized_val_snapshot.csv` = eval's second version (19:57, with plan_legs_json
  and family_* columns). Re-run on it at 20:03: strict columns identical to the first version, same shifts (±0.0001).
  The family_* replay (UP/DOWN pair boarding) shows the same picture: 2,996 scored, wait median 836 s, 18.7% under P50.
- Re-runnable one-shot: `scripts/d2d_diag.py` (component diagnosis).
