# T4.5 Admin tokens and preload (planner)

Status: done (branch v2/planner). Gate decisions are for humans.

## What changed
- `POST /admin/reload-model` and `POST /realtime/clock` now require header `X-Admin-Token`.
  - `ADMIN_TOKEN` unset (default): both endpoints return **403** "admin endpoints are disabled" (AGENTS.md section 5: "unset = admin endpoints disabled").
  - `ADMIN_TOKEN` set: missing or wrong header returns **401**; comparison uses `hmac.compare_digest`.
  - Read-only endpoints (`/journey`, `/health`, `/realtime/status`, `/realtime/eta`, `/stops/search`) are unchanged. The UI does not call either admin endpoint.
- Preload: `app.preload()` runs at startup and after a successful reload. It loads the network, the travel-time tables, the v3 XGBoost model (was lazy-loaded on the first `/journey`), the ml quantile band model when `V2_BAND=1` and ml's `predict.band` is present, the pooled-wait index when `V2_WAIT=pooled`, and the door-to-door shifts when `V2_BAND=1`.
- `/health` now has `models_loaded` (what was loaded, or the error), `admin_enabled` and `flags`.
- Speed-up found while preloading: single-row XGBoost predictions with xgboost's default thread pool take ~9 ms each on this (shared) machine, versus 0.32 ms with `nthread=1` (micro-benchmark, 200 calls). Preload sets `nthread=1` on the v3 booster and on ml's quantile booster.

## Flag
`ADMIN_TOKEN` (string; unset = admin endpoints disabled).

## Files
`planner/app.py`, `planner/tests/test_v2_api.py`.

```

```
