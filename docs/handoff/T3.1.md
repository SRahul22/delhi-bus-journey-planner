# T3.1 Per-segment Kalman update (realtime) — done (behind V2_LIVE=kf, default stays ratio)

## What changed
- `realtime/kf.py` (new): `SegmentKF`. State per flat route segment x = log(observed/historical) stored as cell level + deviation, variance P; 3x3 km cells (from the existing 1 km grid). Between measurements: cell decays to 0 with tau_c, deviation decays to the cell with tau_s, P += q*dt (capped at P0). Measurement noise R = sigma^2, sigma = ln(p85/p50)/1.0364 per segment and hour (floor 0.05). Measurements in the same 60 s bin are combined in information form; the cell is updated with every measurement in it (noise R + 0.04), then the segment. Forecast at horizon h: x_c e^(-h/tau_c) + d e^(-h/tau_s), var = min(P + q h, P0); exp clipped to [0.6, 2.5].
- `realtime/live_state.py`: `LiveState(mode=)` / env `V2_LIVE` (ratio|kf, default ratio). In kf mode `refresh()` advances the KF with new observations (restarts if the clock moves back), the snapshot carries `kf` state, `logr` = h=0 forecast, and `arrivals()` (ETAs) uses horizon forecasts per segment. `compute(n_max=)` for leak-free offline eval. `_trim` keeps the KF cursor aligned. Ratio mode is byte-for-byte the v1 path.
- `realtime/rt_model.py`: in kf mode `ride()` uses the forecast at each segment's horizon instead of the v1 weight fade. `cum()` (RAPTOR scan) still uses h=0 log ratio x v1 fade (documented limitation).
- `realtime/kf_params.json`: fitted parameters (copied from `E:\hackathon-work\v2\realtime\kf_params.json`).
- `realtime/tests/test_kf.py`: 6 unit tests (no-obs, update toward measurement and cell, relaxation = forecast, incremental == bulk, clip, contract 4). `python -m pytest realtime/tests -q` -> 6 passed (Windows, planner venv).

## Fit (22 Oct ONLY)
Objective: weighted MSE (weights = min(hist,300)/60, as v1) of segment log-ratio forecasts for every traversal starting 0-60 min after snapshots taken every 10 min 07:00-21:00 (340k pairs, only observations unknown at T). Grid tau_s {300,900,1800,3600} x tau_c {1800,3600,7200,14400} x q {2e-6,2e-5,1e-4} (`kf_grid_22.csv`). Best: **tau_s = 3600 s, tau_c = 14400 s, q = 2e-6** (wmse 0.11707). Fixed, not tuned: P0 0.09, Pc0 0.04, rc_add 0.04, step 60 s.
Caveat: best point is at the grid edge for tau_s, tau_c and q; a wider grid on 22 Oct is the obvious next step (do not widen it on 28/30).
