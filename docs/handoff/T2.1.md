# T2.1 Headway statistics and wait formula · data

Status: done. Behind `V2_WAIT=gaps` (default `v1`). Gate G2 is for eval and humans.

## What changed
- `model/scripts/build_headways_v2.py <days> <out.csv>` (new): contract 2, built from raw stop visits (A1), not from
  map-matched passings. Gaps are between consecutive departures (`t_last`) of a route at a stop. Revisits by the
  same vehicle less than 600 s apart are merged. Gaps must satisfy 0 < gap ≤ 3 h, and each gap is assigned to the
  IST hour of its midpoint. Holidays 02 and 20 Oct are pooled with weekends.
  Columns: stop_id, route_id, hour, daytype, n, median_headway_s, mean_headway_s, mean_sq_headway_s,
  expected_wait_s (extra column: mean(H²)/(2 mean H), uncapped), wait_p85_s, usable_share (diagnostic).
- wait_p85_s is the **exact** 85th percentile for the card's simulation (a gap is picked with probability proportional
  to its length, and the wait is uniform within it). It solves Σmax(H−w,0) = 0.15 ΣH; a unit test checks it against
  Monte Carlo.
- `planner/ttmodel.py`: with `V2_WAIT=gaps` (and also `pooled`, as the base for T2.2), the wait for a
  (stop, route, hour, daytype) cell is min(mean(H²)/(2 mean H), 1200 s) when the cell has n ≥ 20 gaps
  (`V2_WAIT_MIN_N`). Otherwise the v1 value is used. Per A1, **usable_share is not used as a filter**.
  New: `model.wait85` arrays and `wait_p85_s(ri, i, t_sec, dt)`. These come from the gaps file, else
  1.7 × the v1 wait (the fixed-headway value). The file is found at `V2_HEADWAYS`, else
  `MODEL_DIR\v2\stop_headways_v2.csv`, else `E:\hackathon-work\v2\data\stop_headways_v2.csv`.
- Files: `E:\hackathon-work\v2\data\stop_headways_v2.csv` (days 01-24, 1.68 M rows, 576k with n ≥ 20) and
  `stop_headways_v2_1_18.csv` (days 01-18, for validation).
- Tests: `model/scripts/test_headways_v2.py` (3 passed, run with the planner venv's pytest).
- `model/scripts/validate_waits.py`: the validation below.

## Validation (19-24 Oct; tables from 01-18 only; nothing tuned)
Truth: the random-arrival wait implied by the 19-24 stop-visit gaps per (stop, route, hour, daytype) cell, weighted by
gap time (that is, by arrivals). **Caveat:** truth uses the same visit definition as v2, so it is not independent.
Missed visits (about 7.5%) inflate both. The independent check is eval's realized door-to-door waits (T0.2/G2).

| cells | method | bias | MAE | median abs err | P(wait ≤ p85) |
|---|---|---|---|---|---|
| both have a value (396k) | v1 median/2 (passings) | −351 s | 368 s | 312 s | 0.543 (1.7 × v1) |
| both have a value (396k) | v2 gaps (n ≥ 20) | +27 s | 155 s | 121 s | 0.846 |
| all v1 cells (601k) | v1 | −287 s | 315 s | 274 s | 0.568 |
| all v1 cells (601k) | v2 + v1 fallback | −39 s | 176 s | 134 s | 0.766 |
Mean true wait in these cells: 804 s and 904 s. v2 cells with n ≥ 20 cover 36% of arrival time (v1 tables cover 82%).

Planner smoke test (4 OD pairs × 4 departures): the best option gets 0-31 min longer, from longer waits
(Kashmere Gate→CP 09:00: 42→47 min, wait 3.2→7.5 min). Latency is unchanged: p50 about 510 ms in both modes on
the shared, loaded machine, so the slowdown is not from this change.

## Open issues
- Why v1 is so low: median/2 ignores gap irregularity. With bunching, mean(H²)/(2 mean H) is well above median/2.
  Missing buses in the passings would push v1 gaps up, not down, so the formula, not coverage, explains the gap.
  Eval should confirm with realized waits (T0.2) before G2.
- Lowering `V2_WAIT_MIN_N` would raise coverage above 36%. Not done, because the card fixes n ≥ 20.
- The wait_p85 fallback (1.7 × v1) is a stand-in; T2.5 (deferred) would need it.
